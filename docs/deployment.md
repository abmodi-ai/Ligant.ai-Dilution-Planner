# Deployment notes

- **Architecture.** A Cloudflare Pages project (`ligant-dilution-planner.pages.dev`) behind a route worker (`ligant-dilution-planner-router`) on `benchtools.ligant.ai`, as every sibling tool is built. The worker and its config are in `deploy/router/`; the runbook, and what this session could not do, are in `deploy/README.md`.
- **Address.** `https://benchtools.ligant.ai/dilution-planner/` — slug decided under owner delegation (`docs/decisions.md` D-4). `src/config.js` carries the slug, the title, the citation string and the repository URL as single strings. The owner also announces the tool as `https://benchtools.ligant.ai/Dilution-Planner`; the route worker redirects that, and any other casing of the prefix, once to the canonical lowercase address (24 September 2026).
- **Artefact.** Static files: `index.html`, `styles.css`, `src/**` (native ES modules), `fonts/**`. `npm run build` produces `dist/` with Vite; serving the source tree unbundled works identically (the page is plain HTML + ES modules). No server-side component; no runtime dependency.
- **CSP.** The page carries a meta CSP, and `public/_headers` ships the response-header version with it, including the `frame-ancestors 'none'` that a meta element cannot deliver, plus `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff` and the cache policy. The route worker passes upstream headers through unchanged.
- **One third-party request, by decision.** Since 24 September 2026 the page admits Cloudflare Web Analytics, injected by the host on `benchtools.ligant.ai`: the beacon script from `static.cloudflareinsights.com`, reporting to this origin's `/cdn-cgi/rum`. The CSP allows exactly those two and nothing else outside `'self'`, in both the meta element and `public/_headers`, and `test/deploy-config.test.js` fails if either admits more. The mark and the favicon are drawn inline, so no asset request exists to leak. The built artefact itself makes 8 same-origin requests and none elsewhere; the beacon exists only where the host injects it. Verify with `node scripts/viewport-check.mjs <deployed url>` (network monitoring is registered before page load) in a real browser against the deployed address, and again after any CDN configuration change (acceptance 22).
- **Cache.** Fonts and scripts can be cached; `index.html` should not be cached longer than the deployment cadence.
- **Acceptance items that only the deployed address can satisfy:** 22 (no transmission), 28 (bench sheet printed), 29 (viewport, `docs/D5-browser-configuration.md`).

- **Browser storage on the shared origin.** C3 calls no storage API. But every tool is served from one origin, `https://benchtools.ligant.ai` — an origin is scheme + host + port, so the path does not separate them — and C4 writes `c4.state.v1` (its retention feature, its finding B2). That entry will therefore be visible from C3's page, and from every sibling's. Acceptance 24 for C3 is "C3 writes nothing"; "the origin holds nothing" is not C3's to satisfy and is gated on C4's removal. The same applies on `localhost:5173`, which C3 and C4 dev servers share by Vite default (the owner's T4).
